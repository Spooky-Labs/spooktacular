macOS virtualization for teams · Apple silicon

Install macOS once. Then create VMs in seconds.

Spooktacular installs macOS into one shared base image, then gives every VM its own copy-on-write overlay. The first VM takes twenty minutes and asks for permission once. Every VM after that takes about a second and asks for nothing.

create agent --openclaw --publish 18789:18789

Your VM's services, on localhost

Every VM gets its own private subnet and a reserved address, so spook ip is a lookup rather than a guess. Publish a guest port and reach it on the host the way you would a container.

spook create agent --openclaw --publish 18789:18789
open http://localhost:18789

create runner-01 --github-runner

Runners that register themselves

One command creates the VM, mints a short-lived registration token from a personal access token held in the Keychain, boots headless, and waits until GitHub reports the runner online. No golden image to maintain, no manual first login.

spook create runner-01 --github-runner --github-repo your-org/repo --github-token-keychain your-org --ephemeral

An ephemeral runner exits after one job, and resetting the VM discards its overlay — so the next job starts from the base image, which the framework only ever reads.

What it is

Guests
macOS and Linux macOS from an IPSW into a shared base image; Linux from cloud images with cloud-init.
Storage
ASIF base plus per-VM overlay Apple's DiskImageKit. Ten VMs cost about one base image plus whatever each one writes.
Networking
A vmnet network per VM Reserved addresses and published ports. VMs are isolated from each other by default.
Provisioning
A first-boot script, run as root The guest reports completion over vsock with its exit code, so nothing polls for readiness.
Interfaces
CLI, SwiftUI app, HTTP API 27 commands. The app and the CLI share one engine, so neither is a second-class path.
Licence
MIT no paid tier

Where it fits

Spooktacular is built for teams running a fleet: multi-tenant access control, an mTLS control plane, and an append-only audit log, on Apple's own Virtualization framework with no kernel extension.
